# Telegator — цели, решения, очередь

## Цель

Свой клиент Telegram для владельца и сотрудников (macOS + Windows):

1. Боковая панель Telegator в окне чата. Кнопки и пункты меню — с сервера
   владельца; действия в Telegram выполняет сервер своей сессией; клиент —
   окно: сообщает «выбрали X для сообщения Y в чате Z» и вставляет текст в поле.
2. Фичи, которых нет в официальном клиенте (список ниже).

## Принятые решения (не пересматривать без нового основания)

| Решение | Почему |
|---|---|
| База — чистый `telegramdesktop/tdesktop` | один код на macOS и Windows |
| Готовый форк (AyuGram) за основу не берём | взять нужное ≈ 2 900 строк; выпилить лишнее ≈ 25 800 строк + зацепки в 134 файлах Telegram |
| Наш код — в отдельной папке, в файлы Telegram — точки вызова | дешёвые обновления |
| Сборка — локально на Mac владельца; GitHub Actions (репозиторий публичный) — запасной путь и будущая Windows | владелец поставил Xcode (22.09.2026), облако — 85 минут на сборку; GPL выполняется |
| Приложение будет переименовано в Telegator | нельзя использовать имя/логотип Telegram; бонус — ставится рядом с официальным клиентом |
| Встроенное автообновление выключено | иначе Telegram заменит форк официальной сборкой |
| Контент с таймером не сохраняется никогда | п. 1.4 условий Telegram API |
| Обход защиты от копирования — делаем | в условиях API не упомянут; риск принят владельцем |
| Основной интерфейс — боковая панель справа: веб-страница с сервера владельца во встроенном webview | содержимое (профиль клиента, админка, подсказки нейросети) часто меняется — меняем страницу на сервере без пересборки и раздачи клиента |
| Панель — только для аккаунта обменника; какой это аккаунт и адрес страницы — в локальном конфиге | бизнес-специфика вне репозитория |
| Нативные кнопки в самом клиенте — только немногие стабильные | каждое изменение клиента = сборка и раздача |
| Сотрудникам раздаём после базовых фич (владелец 21.09.2026) | раздавать пока нечего |
| ID в профиле — встроенная настройка Telegram «Show Peer IDs in Profile» (Настройки → Продвинутые → Экспериментальные), своего кода нет | уже есть в Telegram (владелец 22.09.2026) |
| Поиск по ID — только среди чатов и контактов аккаунта, без чужого бота (AyuGram отправляет ID в `@tgdb_search_bot`) | ID клиентов не уходят посторонним; без известного access hash Telegram чат не открывает |
| Кнопки и пункты меню сообщения — с сервера владельца; действия в Telegram (отправка, закреп, реакции) выполняет сервер своей сессией; клиент — окно | меню и действия меняются без новой сборки и раздачи; у клиента нет своих «рук» (владелец 23.09.2026) |
| Встроенной страницы нет: без адреса панели — надпись «Панель не настроена» | прежняя панель с заготовками оказалась не тем, что нужно (владелец 23.09.2026) |
| Подтверждение и выбор перед действием — на странице сервера, а не в окне клиента | ответ сервера меняется без раздачи клиента (23.09.2026) |
| Горячих клавиш у панели нет | владелец не просил (22.09.2026) |
| Своё подтверждение звонка не делаем | в Telegram 7.x исходящий звонок начинается только кнопкой «Начать звонок» |
| Защита от копирования: копировать текст и сохранять медиа можно, пересылать — нет | пересылку из защищённых чатов запрещает сервер Telegram |
| Все сборки на Mac — одна папка данных `~/Library/Application Support/Telegator/` | вход не слетает при новой сборке и запуске двойным щелчком (просьба владельца, 23.09.2026) |

## Сделано

- PoC: кнопка `TEST` в поле ввода отправляла фиксированный текст штатным
  механизмом отправки; 22.09.2026 стала кнопкой показа панели.
- Репозиторий, облачная сборка macOS (Debug), кеш библиотек, секреты API.
- Модуль `telegator/` (`Telegram/cmake/telegator.cmake`); кнопки у поля
  ввода — `telegator/telegator_compose_buttons.*`, в `history_widget` — точки вызова.
- Переименование в Telegator: имя, bundle id `io.github.kdedushev.telegator`,
  папка данных, AppId, AppUserModelId; ссылки `tg:` и ярлык Windows остаются
  за официальным клиентом. Проверено в сборке рядом с Telegram Desktop.
  Иконки пока от Telegram.
- Локальная сборка на Mac владельца (Xcode 27, macOS 12+): библиотеки в
  `~/Projects/telegator-wt/`, порядок — `TELEGATOR.md`.
- Одна папка данных для всех сборок на Mac (точка — `logs.cpp`): вход в
  аккаунт сохраняется между сборками и при запуске двойным щелчком.
- Поиск чата по числовому ID в обычном поле поиска
  (`telegator/telegator_id_search.*`, точка вызова — `dialogs_inner_widget`):
  `123456789`, `1 234 567 890`, `id: …`, Bot API `-100…` и `-…`; неизвестный ID
  ждёт загрузки списка чатов и догружает архив. Проверено владельцем
  (22.09.2026).
- Боковая панель: значок в шапке чата и у поля ввода (бывшая `TEST`);
  страница сервера из `telegator.json`, без адреса — «Панель не настроена»;
  вставка только в тот чат, для которого нажата кнопка; ширина — мышью,
  запоминается. `telegator_panel.*`, `telegator_field.*`.
- Мост окна v1 (23.09.2026, раздел ниже): версия клиента, пункты меню
  сообщения со страницы, открытие окна по пункту и по просьбе страницы.
  Прежние встроенные заготовки на панели и «Реквизиты» с отправкой и
  закрепом из клиента убраны.
- Копирование текста и сохранение медиа в чатах с защитой от копирования;
  пересылка, выгрузка чата и настройка защиты — по настоящему флагу
  (`PeerData::allowsForwardingReal`); медиа с таймером защищены по-прежнему.
- Копирование из защищённых чатов собрано и прошло независимое ревью.
- Нажатие на многострочный моноширинный текст копирует его целиком с
  подсказкой «Текст скопирован», как однострочный и как в Telegram для macOS
  из App Store: lib_ui даёт ссылку только однострочному `code`.
  `telegator_mono_copy.*`, точка вызова — `history_view_message`. Блок кода
  (```) по-прежнему копируется кнопкой «копировать» в его шапке.
- Заготовки после «/» — в порядке телефона (Telegram Desktop
  сортирует по номеру) и с текстом первого сообщения вместо «1 сообщение»,
  после «/» — с премиум-эмодзи;
  пока сообщения не загрузились — прежняя надпись. Порядок — поле `order`
  в `Data::Shortcut` (метки `// Telegator`), текст и сортировка —
  `telegator_quick_replies.*`.

## Очередь

1. **Иконки Telegator** — свои вместо логотипа Telegram (нужен рисунок).
2. **Страница панели и действия — на сервере владельца** (вне этого
   репозитория): вход сотрудника и права на данные клиентов, пункты меню через
   `setMenu`, подтверждение на странице; действия в Telegram — сервером своей
   сессией с защитой от двойного нажатия, журналом и исходами «принято /
   отказано / неизвестно»; отзыв конкретного устройства.
3. **Сборка с мостом v1 — владельцу после страницы сервера**: до неё в меню
   сообщения не будет пунктов. Баннер «обновите Telegator» — на странице,
   по `Telegator.version`.
4. Сохранение удалённых сообщений и история правок (образец — AyuGram
   `ayu/data/`, ~4 000 строк с общим хранилищем, SQLite встроена). Свой
   фильтр контента с таймером, срок хранения, очистка, миграция схемы.
5. **Раздача сотрудникам**: релизные библиотеки и релизная сборка macOS,
   затем Windows (на основе `.github/workflows/win.yml`; webview там —
   WebView2), публикация в GitHub Releases.

Отложено владельцем 22.09.2026 (обзор форков): компактный список чатов,
скрыть Stories, ID и точное время сообщения, режим невидимки, пересылка
одного сообщения в несколько чатов, маскировка имён при показе экрана,
10 аккаунтов вместо 3, дата регистрации аккаунта клиента, источник
скриншота. Не советуем: локальные папки сверх лимита, фильтры сообщений,
«картинка сообщения», местный премиум, ускоритель загрузки.

## Мост окна v1

Страница панели получает `window.Telegator` (`BridgeScript()` в
`telegator_panel.cpp`). Любое изменение ниже — новый номер
`Telegator.version.bridge`.

| Что | Смысл |
|---|---|
| `version` | `{app: "7.2.9", bridge: 1}` — версия клиента и договора |
| `chat`, `onchat(chat)` | открытый чат: `{account_id, peer: {key, type, id, name, username}}`; без `peer` — чат не открыт |
| `theme`, `ontheme(theme)` | цвета приложения для CSS: `bg`, `fg`, `sub`, `over`, `accent`, `accent-fg` |
| `insertText(text, chatKey)` | текст в поле ввода, только если открыт чат `chat.peer.key == chatKey`; ключ брать в начале запроса, чтобы поздний ответ не попал в другой чат |
| `setMenu([{id, label}])` | пункты меню сообщения с текстом, своего и чужого: до 10, `id` и `label` до 64 знаков; клиент хранит последний список по аккаунту и показывает его и до загрузки страницы; `[]` — убрать |
| `onmenu({item, chat, message})` | выбран пункт: `item` — его `id`, `chat` — как в `onchat`, `message: {id, text, out, forwarded, date}` (`id` строкой, `date` — unix-секунды); скрытое окно открывается, событие приходит после загрузки страницы — обработчик ставить сразу; до загрузки доставляется только последний выбор |
| `open()` | показать окно, если скрыто |

Меню — только для аккаунта с панелью и при заданном адресе страницы; нет его
в форумах, у служебных сообщений и сообщений с таймером. В `onmenu` — только
сообщение из чата, где открыто меню. Отправки, закрепа и реакций в клиенте нет.

## Риски

- api_id один на всех сотрудников.
- Без сертификатов macOS и Windows предупреждают при первом запуске
  (Apple Developer $99/год — решение отложено).
- Сотрудники не узнают об обновлениях сами — баннер показывает страница
  сервера по `Telegator.version`.
- Мобильные клиенты не покрываются.
